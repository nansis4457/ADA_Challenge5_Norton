## 1. 문제

홈에서 오늘의 땀 단계를 확인해도 실제 이동 경로에서 얼마나 오래 실외에 노출되는지는
알 수 없다. 같은 목적지라도 실내 연결 통로와 그늘의 비중에 따라 체감 부담이 달라지지만,
일반 길찾기는 가장 빠른 길과 거리만 강조한다.

## 2. 이 기능이 끝나면

사용자는 지도에서 출발지·도착지·출발 시간을 고르고 도보 경로를 비교할 수 있다.
각 경로의 예상 소요 시간과 실외 노출 시간을 함께 보고, 현재 땀 단계에서 실외 노출이
적을 것으로 예상되는 경로를 선택해 이동 화면으로 넘길 수 있다.

## 3. 사용자 시나리오

### 주 시나리오

```
Given  온보딩을 마쳤고 지도 탭을 연다
When   검색 버튼을 누른다
Then   출발지·도착지·출발 시간을 입력하는 화면이 열린다
```

```
Given  출발지와 도착지를 선택했다
When   경로 계산하기를 누른다
Then   도보 경로와 예상 소요 시간·실외 노출 시간이 함께 보인다
```

```
Given  둘 이상의 경로를 계산할 수 있다
When   실외 노출이 적은 길 보기를 누른다
Then   예상 실외 노출이 더 짧은 후보가 선택되고 지도와 요약이 함께 바뀐다
```

### 예외 시나리오

| 상황 | 결과 |
|---|---|
| 위치 권한 거부 | 지도는 열리고 출발지를 직접 검색할 수 있다 |
| 네트워크 없음 | 지도·경로를 불러오지 못했다는 상태와 다시 시도 액션을 보여준다 |
| 장소 검색 결과 없음 | 입력값을 유지하고 검색어를 바꿀 수 있게 한다 |
| 도보 경로 없음 | 자동차 경로로 대체하지 않고, 다른 장소를 고르게 한다 |
| 노출 구간 데이터 없음 | 비율을 `0%`로 만들지 않고 해당 분석 블록을 숨긴다 |
| 일부 구간만 분석 가능 | 분석 범위와 추정치임을 함께 표시한다 |

## 4. 요구사항

| ID | 요구사항 | 검증 방법 |
|---|---|---|
| R1 | 지도 탭을 열면 지도가 보이고, 위치를 얻은 경우 현재 위치를 구분해 표시한다 | 권한 허용·거부 수동 검증 |
| R2 | 지도 화면의 검색 버튼으로 경로 입력 화면을 열 수 있다 | 화면 전환 테스트 |
| R3 | 출발지와 도착지는 검색 결과에서 장소 하나를 선택해야 확정된다 | 텍스트만 입력한 상태와 선택 후 상태 비교 |
| R4 | 출발 시간을 현재 또는 미래 시각으로 정할 수 있다 | 과거 시각 입력 검증 |
| R5 | 출발지·도착지가 모두 확정되기 전에는 경로 계산을 실행하지 않는다 | 단위·수동 검증 |
| R6 | 계산된 도보 경로의 시작·도착 지점과 경로 선을 지도에 표시한다 | 기준 경로 좌표 대조 |
| R7 | 경로마다 예상 총 소요 시간과 예상 실외 노출 시간을 표시한다 | 고정 응답 대조 |
| R8 | 분석 가능한 경우에만 실내·지하/실외 비율과 구간 막대를 표시한다 | 전체·일부·없음 3상태 |
| R9 | 비율·노출 시간은 추정치이며 현장 상황과 다를 수 있음을 결과와 가까운 곳에 표시한다 | 문구 대조 |
| R10 | 둘 이상의 후보가 있으면 예상 실외 노출이 적은 후보로 바꿀 수 있다 | 후보 전환 테스트 |
| R11 | 같은 조건에서는 땀 단계가 높을수록 실외 노출의 경로 정렬 가중치가 낮아지지 않는다 | 1~6단계 정렬 단위 테스트 |
| R12 | 지도·검색·경로·노출 분석 실패를 서로 구분하고 다시 시도할 수 있다 | 장애 주입 |
| R13 | MapKit에는 별도 키를 저장하지 않는다. 후속 외부 지도 식별자·시크릿은 저장소와 앱 번들에 넣지 않고 로컬 빌드 설정에서 주입한다 | 저장소 비밀값 검사·빌드 설정 대조 |
| R14 | 지도와 외부 데이터의 필수 출처 표기를 가리지 않는다 | 실기기 화면 대조 |
| R15 | VoiceOver에서 검색 버튼, 장소 필드, 경로 선, 비율, 통계, 액션의 의미와 상태가 읽힌다 | 접근성 트리·VoiceOver |
| R16 | 접근성 글자 크기에서 통계와 경유 지점이 잘리지 않고 세로로 재배치된다 | `AX3` 이상 |
| R17 | 화면에 진입하면 즉시 로딩 또는 실패 상태가 보이며 빈 화면으로 머물지 않는다 | 지연 응답 주입 |
| R18 | 이동 시작은 선택한 경로를 004 이동 중 기능에 전달할 수 있는 값으로 만든다 | 값 전달 단위 테스트 |

## 8. 결정과 미해결 질문

- [x] **1차 기본 지도** → MapKit을 사용한다. 네이버 지도 키 발급이 끝나도 화면과
      도메인을 다시 만들지 않도록 지도 화면을 전용 경계 안에 둔다.
- [x] **1차 장소 검색** → MapKit 장소 자동완성과 검색을 사용한다. 검색 문자열만
      입력한 상태와 좌표까지 확정된 장소를 구분한다.
- [x] **1차 도보 경로** → MapKit 도보 경로를 사용한다. 경로가 없으면 자동차 경로로
      대체하지 않는다.
- [x] **실내·지하 분석 범위** → 분석 공급자가 확인한 구간만 계산한다. 공급자가
      없거나 커버리지가 0이면 실내외 비율을 숨긴다. 개발·미리보기에서는 고정 분석값으로
      Figma 상태를 검증하되, 실제 응답처럼 가장하지 않는다.
- [x] **네이버 지도 전환 시점** → 발급 완료 후 별도 결정으로 전환한다. 이번 1차 구현의
      완료를 막지 않는다.

미해결 질문 없음. 실내·지하 실제 데이터 연결은 태스크의 별도 착수 조건으로 관리한다.

# 구현 계획

## 10. 접근

### 1차 구현은 MapKit 한 공급자로 검색과 도보 경로를 잇는다

장소 자동완성, 장소 확정, 도보 경로 계산을 각각 작은 프로토콜 뒤에 둔다. 화면과
도메인은 MapKit 타입을 직접 저장하지 않고 이름·좌표·거리·시간·경로 좌표열만 받는다.
네이버 지도 발급이 끝나면 지도 렌더러만 먼저 바꾸고, 검색·경로 공급자는 별도로
교체 여부를 정할 수 있다.

지도 화면은 `RouteMapView` 안에서 SwiftUI `Map`을 사용한다. 경로는 `MapPolyline`,
출발·도착은 `Marker`, 현재 위치는 `UserAnnotation`으로 표시한다. Figma의 회색 블록과
그려진 경로 이미지는 에셋으로 가져오지 않는다.

### 실내외 분석은 경로 계산과 분리한다

도보 경로가 성공했다고 실내외 분석도 성공한 것으로 취급하지 않는다.
`ExposureAnalyzing`은 경로를 받아 분석 가능 범위와 구간 목록을 돌려준다. 초기 실제
구현은 커버리지 없음이며 결과 화면은 예상 소요 시간과 경로만 보여준다. 고정 분석기는
테스트·미리보기·수동 검증에서만 쓴다.

이렇게 하면 데이터가 없는데 `실내 0%`라고 단정하는 오류를 막고, 이후 지하 연결 통로와
건물 그늘 데이터를 붙일 때 검색·지도 화면을 바꾸지 않아도 된다.

### 탭은 시스템 구조를 사용한다

온보딩 완료 뒤 홈·지도·마이 세 탭을 시스템 탭으로 구성한다. 각 탭은 자신의
`NavigationStack`을 가지며, 지도 탭 안에서 `지도 → 경로 입력 → 경로 결과`가 이동한다.
004의 이동 시작은 이번에는 선택 경로를 값으로 넘기는 경계까지만 만들고 실제 이동 화면은
후속 스펙에서 구현한다.

### 검토했지만 택하지 않은 것

- 네이버 자동차 경로를 도보 경로처럼 사용 — 경로 성격이 달라서 제외
- 입력 문자열을 곧바로 장소로 간주 — 동명 장소와 잘못된 좌표를 구분할 수 없어 제외
- 분석 데이터가 없을 때 전 구간을 실외로 간주 — 상한값을 실제 추정치처럼 보이게 해 제외
- MapKit 타입을 화면 상태에 그대로 저장 — 지도 공급자 교체 범위를 넓혀 제외

## 11. 규칙 점검

| 규칙 | 해당 | 지키는 방법 |
|---|---|---|
| 단정하지 않는다 | ✅ | 추천·노출 문구에 `예상`, `추정`, `~수 있어요`를 사용한다 |
| 추정치는 추정치로 | ✅ | 분석 블록 가까이에 고지하고 부분 커버리지를 함께 표시한다 |
| 습도·풍속을 단계에 두 번 세지 않는다 | ✅ | 경로 정렬은 이미 계산된 땀 단계와 노출 시간만 받는다 |
| 경계값은 한 곳에 | ✅ | 단계별 노출 가중치는 `RouteRankingPolicy` 한 곳에 둔다 |
| 기록이 예측을 고친다 | ⬜ | 005 범위. 현재 프로필에서 계산된 단계를 입력으로만 받는다 |
| 도메인은 순수하게 | ✅ | 경로·분석·정렬 타입은 `SweatDomain`, 공급자 타입 import 금지 |
| 문구는 뷰 밖에 | ✅ | `RouteCopy`에서 화면·오류·접근성 문구를 제공한다 |
| 색과 글꼴은 토큰으로 | ✅ | 기존 DesignSystem 토큰과 컴포넌트를 사용한다 |
| 접근성은 마감이 아니다 | ✅ | 지도 대체 설명, 비율 결합 낭독, `AX3` 대체 배치를 처음부터 구현한다 |
| Swift 6 | ✅ | 공급자 콜백을 async 경계로 감싸고 전송 타입은 `Sendable`로 둔다 |

## 14. 테스트 계획

| 대상 | 방식 | 케이스 |
|---|---|---|
| 경로 모델 | 단위 | 빈 좌표열 거부, 음수 거리·시간 거부 |
| 노출 분석 | 단위 | 없음·부분·전체, 합계와 비율, 0으로 거짓 표시하지 않음 |
| 경로 정렬 | 단위 | 같은 후보에서 단계 1~6의 노출 가중치 단조 증가 |
| 장소 검색 어댑터 | 고정 대역 | 빈 검색어, 결과 없음, 중복, 선택 해석 실패 |
| 도보 경로 어댑터 | 고정 대역·수동 | 도보 지정, 후보 여러 개, 경로 없음, 네트워크 실패 |
| 화면 상태 | 단위 | 입력 미완료, 검색 중, 계산 중, 결과, 각 실패 |
| 화면 | 수동 | Figma 06~08, 권한 허용·거부, `AX3`, VoiceOver |

규칙 회귀 테스트는 분석값이 없을 때 `0%` 문자열을 만들지 않는지, 자동차 경로가
도보 실패의 폴백으로 호출되지 않는지를 확인한다.

## 15. 리스크

| 리스크 | 영향 | 대응 |
|---|---|---|
| MapKit의 국내 장소·도보 경로 품질 편차 | 검색 결과 또는 경로 없음 | 실패 상태를 분리하고 네이버 전환 경계를 유지 |
| 실제 실내·지하 데이터 미연결 | 핵심 비율 블록이 숨겨짐 | UI·도메인을 고정 분석기로 먼저 검증하고 실제 공급자는 별도 착수 조건으로 관리 |
| 지도 공급자 전환 시 타입 누수 | 대규모 재작성 | MapKit 타입은 `RouteData`와 `RouteMapView` 밖으로 내보내지 않음 |
| 지도 로딩과 검색 요청 경합 | 화면 지연 | 지도와 검색 상태를 분리하고 이전 검색을 취소 |
| 접근성 크기에서 지도 비중 과다 | 결과 텍스트 탐색 어려움 | 결과 지도 높이를 제한하고 지도 다음에 요약을 순서대로 배치 |
