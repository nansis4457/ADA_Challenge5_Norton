## 1. 문제

앱은 모든 사용자에게 같은 등급을 보여준다. 그런데 같은 체감온도에서도
땀이 잘 나는 사람과 아닌 사람의 경험은 다르다. 이동수단과 야외 노출 시간도
사람마다 달라서, 같은 경로라도 부담이 같지 않다.

`SweatStageEngine`은 이미 민감도를 받을 준비가 되어 있지만
(`Sensitivity`, 000에서 구현), **그 값을 물어보고 기억하는 곳이 없다.**
지금은 항상 `.normal`로 계산된다.

## 2. 이 기능이 끝나면

처음 앱을 연 사용자가 세 가지를 답하고 홈으로 들어간다 — 땀 민감도, 이동 패턴,
알림 수신 여부. 답한 값은 기기에 남아 다음 실행부터 등급 계산에 쓰인다.
나중에 마이페이지에서 다시 고칠 수 있다.

## 3. 사용자 시나리오

### 최초 실행
```
Given  앱을 처음 실행한다
When   민감도 → 이동 패턴 → 알림 순서로 답한다
Then   홈이 뜨고, 고른 민감도가 반영된 등급이 보인다
```

### 재실행
```
Given  온보딩을 마친 적이 있다
When   앱을 실행한다
Then   온보딩 없이 홈이 바로 뜬다
```

### 값 수정
```
Given  마이페이지에서 "내 땀 민감도 다시 설정"을 누른다
When   값을 바꾸고 저장한다
Then   마이페이지로 돌아가고, 바뀐 값이 프로필 요약에 보인다
```

### 예외
| 상황 | 결과 |
|---|---|
| 알림 권한 거부 | 온보딩은 정상 완료된다. 알림만 오지 않는다 |
| "나중에 할게요" | 권한을 요청하지 않고 완료한다 |
| 이미 권한이 있는 상태로 재진입 | 다시 묻지 않는다 |
| 온보딩 도중 앱 종료 | 다음 실행에 온보딩을 처음부터 다시 한다 |

마지막 항목은 의도된 단순화다. 3단계짜리 흐름에 중간 저장을 넣을 이유가 없다.

## 4. 요구사항

| ID | 요구사항 | 검증 방법 |
|---|---|---|
| R1 | 온보딩을 마치기 전에는 앱을 다시 켜도 온보딩이 뜬다 | 완료 전 종료 후 재실행 |
| R2 | 온보딩을 마치면 다음 실행부터 홈으로 바로 간다 | 완료 후 재실행 |
| R3 | 고른 민감도·이동수단·이동시간이 앱을 껐다 켜도 유지된다 | 재실행 후 마이페이지에서 확인 |
| R4 | 고른 민감도가 등급 계산에 실제로 반영된다 | 같은 체감온도에서 민감도만 바꿔 등급이 달라지는지 |
| R5 | 각 단계는 기본값이 이미 선택된 상태로 시작한다 (보통 · 지하철 · 20~40분) | 화면 진입 시 |
| R6 | "알림 허용하고 시작"은 시스템 권한을 요청하고, 결과와 무관하게 온보딩을 끝낸다 | 허용·거부 양쪽 |
| R7 | "나중에 할게요"는 권한을 요청하지 않고 온보딩을 끝낸다 | 시스템 대화상자가 뜨지 않음 |
| R8 | 마이페이지에서 재진입하면 뒤로가기가 생기고 CTA가 `저장`으로 바뀐다 | 두 경로 비교 |

| R10 | 재진입에서 저장하면 마이페이지로 돌아간다 (홈이 아니라) | |
| R11 | 최초 온보딩에는 탭 바가 없다. 재진입 시에는 있다 | 두 경로 비교 |
| R12 | 선택지가 VoiceOver에서 선택 상태로 읽힌다 | VoiceOver 켜고 순회 |
| R13 | 접근성 글자 크기에서 문구가 잘리지 않는다 | `AX5`에서 세 화면 |
| R14 | 화면 문구가 §6과 정확히 일치한다 | 대조 |

### 공통

|---|---|---|

### 01 민감도
| 키 | 문구 |
|---|---|
| `step` | STEP 1 / 3 |
| `heading` | 땀은 얼마나\n많이 흘리는 편인가요? |
| `sub` | 같은 날씨에서도 사람마다 느끼는 정도가 달라요. 등급과 추천을 조정하는 데 쓰입니다. |

### 03 알림
| 키 | 문구 |
|---|---|
| `step` | STEP 3 / 3 |
| `heading` | 외출 전에\n알려드릴까요? |
| `sub` | 땀 부담이 높은 날 아침, 그리고 이동 중 더위가 심해질 때만 보냅니다. |
| `preview.label` | 미리보기 |
| `preview.title` | 오늘은 땀이 많이 날 수 있어요 |
| `preview.body` | 체감온도가 높아요. 가능하면 그늘이 많은 길로 이동해보세요. |
| `cta.allow` | 알림 허용하고 시작 |
| `cta.later` | 나중에 할게요 |

### 규칙 「단정하지 않는다」 점검
전부 `~일 수 있어요`·`~해보세요` 어투다. 분비량 수치·배수·등식 표현 없음.
`preview.*`는 알림 문구이므로 화면 카피(`SweatCopy`)와 별개로 관리한다.

> **Figma와 개발가이드가 한 글자 다르다** — Figma는 `오늘은 땀 많이 날 수 있어요`,
> 개발가이드 §7은 `오늘은 땀이 많이 날 수 있어요`. **개발가이드를 따른다.**
> 문구의 출처는 개발가이드이고 Figma는 그것을 옮긴 것이므로, 어긋나면 원문이 맞다.
> Figma도 함께 고친다.

# 구현 계획

> 여기서부터는 *어떻게*다. 위쪽은 *무엇을·왜*.

|---|
| `SweatFeatures` | 화면이 처음 생긴다. 앱 타깃에 두면 "얇게 유지"가 첫 화면부터 무너지고, `lint-tokens.sh`의 대상 경로도 앱 타깃 전체가 된다 |
| `SweatPersistence` | 프로필 저장이 필요하다. 도메인에 넣으면 순수성이 깨지고(§규칙 「도메인은 순수하게」의 취지), 피처에 넣으면 005에서 옮겨야 한다 |

`UserDefaults`는 `Foundation`이라 문자로는 도메인에 넣어도 규칙 「도메인은 순수하게」 위반이 아니다.
그러나 도메인은 **부수효과 없이 테스트 가능해야** 한다는 게 원칙의 취지다. I/O는 밖으로 뺀다.

### 프로필은 키-값, 기록은 SwiftData

이번엔 프로필만 만든다. `SweatPersistence`가 `UserDefaults`를 감싼 `ProfileStore`를 갖는다.
005에서 SwiftData 기반 `LogStore`가 같은 패키지에 추가된다. 마이그레이션은 없다.

### 문구는 뷰 밖에 둔다

`SweatCopy`는 **단계 관련** 문구의 출처다. 온보딩 문구는 단계와 무관한 UI 텍스트이므로
`SweatFeatures`의 `OnboardingCopy`에 따로 모은다. 규칙 「문구는 뷰 밖에」는 "뷰에 문자열 리터럴 금지"이지
"모든 문구를 도메인에 넣으라"가 아니다.

String Catalog은 쓰지 않는다. 뷰의 리터럴을 자동 추출하는 방식이라
뷰에 리터럴을 두도록 **부추긴다.** 현지화가 실제 요구가 되면 그때 이 enum을 감싼다.

### 홈이 없으므로 자리표시자를 둔다

R4(민감도가 등급 계산에 반영된다)를 눈으로 확인하려면 결과를 보여줄 화면이 필요한데
홈은 002다. 온보딩 완료 후 **계산된 단계와 문구만 표시하는 임시 화면**을 둔다.
002가 이 화면을 대체한다.

### 검토했지만 택하지 않은 것

- **앱 타깃에 화면 두기** — 지금은 편하지만 001~005 내내 앱 타깃이 비대해진다
- **온보딩 중간 저장** — 3단계짜리 흐름에 재개 로직을 넣을 이유가 없다 (스펙 §3)
- **String Catalog** — 위 참조

## 12. 데이터 흐름

```
온보딩 선택
   ↓
UserProfile (Codable)
   ↓  ProfileStore.save
UserDefaults
   ↓  ProfileStore.load          앱 실행 시
UserProfile
   ↓
SweatStageEngine.stage(체감온도, profile.sensitivity, profile.calibrationOffset)
   ↓
SweatStage → SweatCopy → 화면
```

`transport`·`outdoorDuration`은 이번에 **저장만** 된다. 소비는 003이다.
저장해두지 않으면 003에서 다시 물어봐야 한다.

---

## 13. 모드 두 가지

`OnboardingFlow`는 진입 방식에 따라 다르게 동작한다.

| | 최초 실행 | 마이페이지에서 편집 |
|---|---|---|
| 시작 단계 | 1단계 | 지정된 단계 하나 |
| 뒤로가기 | 없음 | `← 마이페이지` |
| CTA | `다음` → 다음 단계 | `저장` → 즉시 종료 |
| 3단계(알림) | 포함 | **건너뜀** |
| 탭 바 | 없음 | 있음 |
| 끝난 뒤 | 홈 | 마이페이지 |

마이페이지가 005에 생기므로, 이번에는 **자리표시자 화면에 편집 진입 버튼**을 둬서
R8~R11을 검증한다. 005가 진짜 진입점을 연결한다.

## 14. 외부 의존

| 의존 | 용도 | 실패 시 |
|---|---|---|
| 알림 권한 요청 | 3단계 | 거부돼도 온보딩은 완료된다 (R6) |
| 키-값 저장 | 프로필 | 손상되면 기본값으로 시작 (§7) |

위치 권한은 002다. 이번에 건드리지 않는다.

## 15. 테스트 계획

| 대상 | 방식 | 케이스 |
|---|---|---|
| `Transport`·`OutdoorDuration` | 단위 | `rawValue` 고정 — 바뀌면 저장된 데이터가 깨진다 |
| `ProfileStore` | 단위 | 왕복 저장, 빈 저장소 기본값, **손상된 데이터 복구** |
| 기본값 | 단위 | 보통 · 지하철 · 20~40분 (R5) |
| 온보딩 문구 | 단위 | 000의 금지 패턴 린트를 온보딩 카피에도 적용 (R14) |
| 흐름 | 수동 | 최초/편집 두 경로, 권한 허용·거부 (R1·R2·R6~R11) |
| 접근성 | 수동 | VoiceOver 선택 상태, `AX5`에서 잘림 (R12·R13) |

`ProfileStore` 테스트는 실제 `UserDefaults`를 건드리지 않도록 **별도 suite name**을 쓴다.

### 손상 데이터

디코딩에 실패하면 기본 프로필로 시작한다. 크래시하지 않는다.
저장 포맷이 바뀔 001 이후를 대비한 최소한의 방어다.

## 16. 000에서 넘어온 결정 적용

| | 적용 위치 |
|---|---|
| 줄높이는 SwiftUI 기본을 따른다 | 화면 전부. Figma 높이를 목표로 삼지 않는다 |
| Chip 프레임 최소 높이 44pt | `SweatChip` 수정 (2단계에서 처음 쓰인다) |
| Button·Score·TextField 여백 토큰 정렬 | 컴포넌트 수정 + Figma 반영 |

컴포넌트 수정은 `DesignSystem` 변경이라 001 범위지만 000의 결과물을 건드린다.
**커밋을 분리해서** 무엇이 결정 적용이고 무엇이 신규 기능인지 구분한다.
