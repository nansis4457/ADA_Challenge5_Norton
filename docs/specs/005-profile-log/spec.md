# [005] 마이페이지 · 자가 기록 · 지수 개선 — 스펙

**상태** Implemented
**브랜치** `005-profile-log`
**작성** 2026-08-26

## 1. 문제

사용자는 앱의 예측이 자신의 실제 체감과 맞았는지 남길 수 없고, 앱이 개인차를 학습했는지
확인할 수도 없다. 온보딩에서 정한 민감도와 이동 패턴을 다시 확인하거나 수정할 화면도 없다.

## 2. 이 기능이 끝나면

사용자는 마이페이지에서 자신의 설정과 기록 요약을 보고, 하루 한 번 실제 땀 체감과 불편
요인을 기록할 수 있다. 충분한 기록이 쌓이면 앱은 제한된 범위에서 개인 보정값을 갱신하고,
어떤 기록 때문에 기준이 바뀌었는지 최근 비교와 함께 설명한다.

## 3. 사용자 시나리오

### 주 시나리오

```
Given 오늘의 날씨 예측을 확인했다
When  마이페이지에서 1~5점과 불편 태그를 골라 저장한다
Then  오늘 기록이 기기에 저장되고 마이페이지 통계가 갱신된다
```

```
Given 습도 70% 이상인 기록이 5건 이상 쌓였다
When  새 기록을 저장한다
Then  보정값이 최대 ±1.5℃ 안에서 갱신되고 변경 근거가 지수 개선 화면에 보인다
```

```
Given 마이페이지를 연다
When  민감도 또는 이동 패턴 수정을 선택한다
Then  기존 선택값이 보이고 저장 후 요약에 즉시 반영된다
```

```
Given 이동을 마치고 완료 값이 만들어졌다
When  도착 · 오늘 기록하기를 누른다
Then  마이 탭의 오늘 기록 화면이 열리고 관측 가능한 이동 집계만 기록에 전달된다
```

### 예외 시나리오

| 상황 | 결과 |
|---|---|
| 오늘 날씨를 아직 받지 못함 | 기록 화면은 열리지만 저장하지 않고 날씨 확인 안내를 보여준다 |
| 오늘 기록이 이미 있음 | 기존 점수와 태그를 불러와 같은 날짜 기록을 수정한다 |
| 고습도 기록 5건 미만 | 기록은 저장하지만 보정하지 않고 필요한 표본 수를 설명한다 |
| 기록이 없음 | 통계는 `—`, 기록 메뉴는 오늘 기록 없음 상태로 표시한다 |
| 저장 실패 | 입력을 유지하고 저장 실패와 재시도 안내를 보여준다 |

## 4. 요구사항

| ID | 요구사항 | 검증 방법 |
|---|---|---|
| R1 | 마이페이지에서 프로필·기록 통계·설정 요약을 볼 수 있다 | 빈 기록·복수 기록 대조 |
| R2 | 1~5점 중 하나를 선택하고 불편 태그를 여러 개 선택할 수 있다 | 선택 상태·VoiceOver |
| R3 | 기록에는 날짜·예측 단계·실제 점수·태그·관측 환경을 저장한다 | 저장 후 재조회 |
| R4 | 같은 달력 날짜에는 기록 하나만 존재하고 다시 저장하면 수정된다 | 중복 저장 테스트 |
| R5 | 고습도 기록 5건 미만에서는 보정값을 바꾸지 않는다 | 4건 경계 테스트 |
| R6 | 5건 이상에서는 평균 오차의 지수 이동 평균으로 보정하고 ±1.5℃로 제한한다 | 5건·상하한 테스트 |
| R7 | 습도는 학습 표본 선택에만 쓰고 현재 단계 계산에 직접 다시 더하지 않는다 | 도메인 시그니처·회귀 테스트 |
| R8 | 최근 7일의 예측 단계와 실제 점수를 날짜별로 비교한다 | 0·1·7일 데이터 대조 |
| R9 | 보정 적용 여부·표본 수·평균 차이·방향을 문장으로 설명한다 | 결과별 문구 테스트 |
| R10 | 민감도와 이동 패턴을 다시 설정하고 마이 요약에 즉시 반영한다 | 편집 흐름 수동 검증 |
| R11 | 기록과 설정은 기기에만 저장하고 서버로 전송하지 않는다 | 네트워크 호출 검사 |
| R12 | 가장 큰 글자 크기에서도 기록 선택과 리포트가 잘리지 않는다 | 접근성 크기 수동 검증 |
| R13 | 이동 완료 뒤 오늘 기록 화면을 열고 실제 관측된 실외 시간만 저장하며, 분석할 수 없으면 값을 만들지 않는다 | 이동→기록 통합 테스트 |

# 구현 계획

## 10. 접근

순수한 `CalibrationEngine`은 값 타입 기록만 받아 보정 결과를 계산한다. SwiftData 모델과
조회·저장은 `SweatPersistence`가 소유하고, 화면은 조회한 기록을 도메인 입력으로 변환한다.
따라서 저장소나 시뮬레이터 없이 4/5건 경계와 상한을 단위 테스트할 수 있다.

마이 탭은 기존 시스템 `TabView`를 유지하고 내부에 `NavigationStack`을 둔다. 자가 기록과
지수 개선은 푸시 화면이며, 점수·칩·주요 버튼은 기존 DesignSystem 컴포넌트를 재사용한다.
최근 7일 비교는 수동 막대 레이어 대신 Swift Charts를 사용한다.

보정은 체감온도 산식에 습도를 다시 넣지 않는다. 기록 중 고습도 표본이 개인차를
일관되게 보여주는지 판단하는 데만 습도를 쓰고, 결과는 기존 일반 보정값 하나에 반영한다.

## 11. 규칙 점검

| 규칙 | 해당 | 지키는 방법 |
|---|---|---|
| 단정하지 않는다 | ✅ | 체감·원인 문구는 기록과 비교 사실만 말한다 |
| 추정치는 추정치로 | ✅ | 예측과 실제 기록을 범례로 분리한다 |
| 습도·풍속을 단계에 두 번 세지 않는다 | ✅ | 습도는 과거 표본 필터이며 엔진 입력을 늘리지 않는다 |
| 경계값은 한 곳에 | ✅ | 표본·상한·학습률은 `CalibrationEngine` 상수 한 곳 |
| 기록이 예측을 고친다 | ✅ | 5건 경계·상한·설명까지 도메인 결과로 강제한다 |
| 도메인은 순수하게 | ✅ | 엔진은 Foundation 외 의존성이 없다 |
| 문구는 뷰 밖에 | ✅ | `ProfileCopy`에 모은다 |
| 색과 글꼴은 토큰으로 | ✅ | DesignSystem 토큰과 기존 컴포넌트를 쓴다 |
| 접근성은 마감이 아니다 | ✅ | 차트 대체 낭독·선택 상태·큰 글자 세로 배치 |
| Swift 6 | ✅ | 전송 값은 Sendable, SwiftData 접근은 MainActor |
