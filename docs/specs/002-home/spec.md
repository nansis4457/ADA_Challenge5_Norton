## ⚠️ 착수 전 반드시 닫아야 하는 것

**기상청 체감온도 산식이 검증되지 않았다.** 이 화면의 모든 숫자가 거기서 나온다.
`docs/architecture.md` §5.4의 계수를 기상청 원문과 대조하고, 검증 케이스를
단위 테스트로 고정한 뒤에 시작한다.

산식이 다르면 **디자인의 34.2℃가 아니라 산식을 신뢰한다.** 디자인 수치가 바뀐다.

이 스펙은 그 전에도 쓸 수 있지만 구현은 시작하지 않는다.

---

## 1. 문제

001에서 사용자가 민감도를 답했지만, 그 값으로 계산한 결과를 볼 화면이 없다.
지금 앱은 임시 화면에 단계 숫자만 띄운다.

정작 사용자가 알고 싶은 건 세 가지다 — **오늘 얼마나 땀이 날까**, **왜 그런가**,
**하루 중 언제가 제일 힘든가.**

## 2. 이 기능이 끝나면

앱을 열면 지금 있는 곳의 관측값으로 계산한 오늘의 땀 단계가 마스코트와 함께 뜬다.
왜 그 단계인지 궁금하면 한 번 눌러 기온·습도·풍속의 기여도를 본다.
아래로 내리면 시간별·주간 예보가 같은 단계 기준으로 보인다.

## 3. 사용자 시나리오

### 주 시나리오
```
Given  온보딩을 마쳤고 위치 권한을 허용했다
When   앱을 연다
Then   현재 위치의 관측값으로 계산한 단계·멘트·마스코트가 보인다
```

```
Given  홈에서 "더 알아보기"를 누른다
When   등급 상세가 열린다
Then   체감온도·습도·풍속이 각각 얼마나 기여했는지 보인다
```

### 예외
| 상황 | 결과 |
|---|---|
| 위치 권한 거부 | 지역을 직접 고르게 하고, 그 지역 관측값으로 계산한다 |
| 기상청 응답 없음 | 대체 소스로 계산하고 출처를 다르게 표기한다 |
| 둘 다 실패 | 마지막 성공값 + `n분 전 관측` 배지. 빈 화면을 만들지 않는다 |
| 네트워크 없음 | 위와 같다 |
| 캐시도 없는 첫 실행 | 관측값 자리에 로딩, 마스코트는 중립 상태 |

# 구현 계획

> 여기서부터는 *어떻게*다.

## 10. 접근

### 날씨는 두 소스를 겹쳐 쓴다

기상청을 1순위로, 대체 소스를 폴백과 장기 예보 보완에 쓴다.
`architecture.md` §6의 결정을 그대로 따른다.

핵심은 **화면이 소스를 모르게** 하는 것이다. `WeatherRepository`가 어디서 왔는지를
감추고 `Observation`이라는 단일 형태로 돌려준다. 출처 표기만 값에 딸려 나온다.

### 체감온도는 도메인에서 계산한다

산식은 순수 함수다. 기온·습도만 있으면 계산되고 네트워크가 필요 없다.
`SweatDomain`에 넣어 시뮬레이터 없이 검증한다.

**기상청이 체감온도를 직접 주더라도 우리 산식으로 다시 계산하지 않는다** — 주면 그걸 쓴다.
대체 소스의 체감온도는 산식이 달라 **쓰지 않고**, 그 소스의 기온·습도로 우리가 계산한다.
그래야 단계 기준이 한 가지로 유지된다.

### 예보도 같은 엔진을 쓴다

시간별·주간 예보의 단계도 `SweatStageEngine`이 계산한다. 예보 전용 로직을 따로 만들지 않는다.
Figma의 `Weather Face` Level 1~4는 6단계를 4구간으로 묶은 표시용이며,
그 매핑도 도메인에 둔다.

### 검토했지만 택하지 않은 것

- **대체 소스 단독** — 화면에 `기상청`이라 적혀 있고, 그게 이 앱의 신뢰 근거다
- **기상청 단독** — 격자 변환·발표 시각·쿼터를 모두 우리가 떠안고 장애 시 대안이 없다
- **예보용 별도 단계 로직** — 홈과 예보의 단계가 어긋나면 사용자가 먼저 알아챈다

## 12. 출처 표기

화면 헤더에 `기상청`이라고 적혀 있다. 대체 소스가 섞이면 사실과 다르다.

**규칙** — 값마다 출처를 함께 들고 다닌다. 화면은 그 출처를 표시한다.
대체 소스를 쓸 때는 해당 서비스가 요구하는 표기·링크를 함께 넣는다.

이건 법적 요건이기도 하다. 구현 전에 해당 서비스의 표기 조건을 확인한다.

## 15. 테스트 계획

| 대상 | 방식 | 케이스 |
|---|---|---|
| 체감온도 산식 | 단위 | **기상청 공표 사례 대조.** 이 스펙의 전제 |
| 격자 변환 | 단위 | 알려진 좌표쌍 고정 |
| 발표 시각 | 단위 | 매시 40분 전후 경계 |
| 카테고리 파싱 | 단위 | 정상 · 미지 코드 · 결측 |
| 폴백 | 단위 | 1순위 타임아웃 · 빈 응답 · 오류 → 대체 소스 |
| 캐시 | 단위 | TTL 만료, stale 허용, 둘 다 실패 시 마지막 값 |
| 예보 레벨 매핑 | 단위 | 6단계 → 4구간 경계 |

| 화면 | 수동 | 6단계, 권한 거부, 오프라인, `AX3` |
