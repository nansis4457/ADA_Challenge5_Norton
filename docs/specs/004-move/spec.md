# [004] 이동 중 · Live Activity — 스펙

**상태** In Progress
**브랜치** `004-move`
**작성** 2026-08-25

> "문제"~"완료 조건"은 무엇을·왜에 집중한다. 구현 도구는 구현 계획에서 확정한다.

## 1. 문제

경로를 선택하고 `이동 시작`을 눌러도 현재 앱은 선택한 경로를 보관한 뒤 준비 중 안내만
보여준다. 사용자는 이동을 시작한 뒤 얼마나 진행했는지, 남은 거리와 시간이 어느 정도인지,
앱을 닫아도 이동 상태가 이어지는지 알 수 없다.

또한 실내·그늘 구간과 공식 무더위쉼터 데이터가 없는 상황에서 구체적인 우회 효과나 쉼터를
보여주면 추정치를 사실처럼 받아들일 수 있다.

## 2. 이 기능이 끝나면

사용자는 선택한 도보 경로로 이동을 시작하고, 앱 화면과 잠금 화면에서 진행률·남은 거리·
예상 시간을 확인할 수 있다. 근거 데이터가 있는 경우에만 더운 구간, 공식 무더위쉼터,
그늘 우회 선택지를 보고, 데이터가 없으면 기본 진행 정보와 물 마시기 알림만 사용한다.
도착하면 추적을 끝내고 오늘 기록으로 넘길 수 있는 완료 값을 만든다.

## 3. 사용자 시나리오

### 주 시나리오

```
Given  경로 결과에서 도보 경로 하나를 선택했다
When   이동 시작을 누르고 위치 사용을 허용한다
Then   선택한 출발지·도착지와 진행률·남은 거리·예상 시간이 보인다
```

```
Given  이동이 진행 중이다
When   앱을 잠그거나 다른 앱으로 전환한다
Then   잠금 화면에서 같은 이동의 진행률·남은 거리·예상 시간을 확인할 수 있다
```

```
Given  현재 경로 앞 구간과 공식 쉼터 또는 대안 경로를 확인할 수 있다
When   이동 화면을 본다
Then   근거가 확인된 액션만 추정 표현과 함께 보인다
```

```
Given  이동이 진행 중이다
When   물 마시기 알림을 선택한다
Then   10분 뒤 한 번 알림을 받을 수 있고 화면에서 예약 상태를 확인한다
```

```
Given  목적지에 도착했거나 사용자가 이동을 끝내려 한다
When   도착 · 오늘 기록하기를 누른다
Then   위치 추적과 실시간 표시를 끝내고 오늘 기록에 전달할 완료 값을 만든다
```

### 예외 시나리오

| 상황 | 결과 |
|---|---|
| 위치 권한 거부 | 빈 화면에 머물지 않고 자동 진행 추적이 불가능한 이유와 돌아가기·종료 액션을 보여준다 |
| 위치가 일시적으로 없음 | 마지막 확인 시각과 진행 일시 중지 상태를 표시하고 진행률을 임의로 늘리지 않는다 |
| 실내·그늘 분석 데이터 없음 | 진행 정보는 유지하고 해당 설명·쉼터·우회 액션을 숨긴다 |
| 공식 쉼터 데이터 없음 | 일반 편의점을 무더위쉼터로 표시하지 않고 쉼터 액션을 숨긴다 |
| 대안 경로 없음 | 그늘길 우회 액션과 감소 효과를 숨긴다 |
| 알림 권한 거부 | 이동은 계속하며 알림을 켤 수 없다는 상태를 해당 액션 가까이에 보여준다 |
| 실시간 표시를 시작할 수 없음 | 앱 안 진행 화면은 계속 동작하고 실패 이유를 비차단 상태로 남긴다 |
| 앱 재실행 | 저장된 활성 이동이 유효하면 복원하고, 끝난 이동을 새 이동처럼 되살리지 않는다 |

## 4. 요구사항

## 8. 결정과 미해결 질문

- [x] **위치 권한** → `앱을 사용하는 동안`만 요청한다. 활성 이동에서는 시스템의
      백그라운드 활동 표시를 사용하고 항상 허용 권한은 요구하지 않는다.
- [x] **데이터 없음** → 기본 진행 상태를 정상 상태로 취급한다. 분석값을 `0`으로 만들지
      않고 쉼터·우회 추천을 숨긴다.
- [x] **쉼터 명칭** → 공식 데이터에서 확인된 장소만 `무더위쉼터`라고 부른다.
- [x] **동시 이동** → 한 번에 하나만 활성화한다. 새 이동은 기존 이동을 먼저 정리한 뒤
      시작한다.
- [x] **물 알림 수명** → 이동에 속한 임시 알림이므로 이동 종료·취소 시 함께 취소한다.
- [x] **005 연결 전 종료** → 완료 값은 만들되 기록 저장을 가장하지 않고 종료 확인 뒤
      지도 흐름으로 돌아간다.
- [x] **활성 이동 유효 시간** → 마지막 집계 진행값을 저장한 뒤 12시간 안의 미완료 이동만
      복원한다. 원시 위치 이력은 저장하지 않고 완료·손상·만료 상태는 즉시 지운다.

미해결 질문 없음. 실제 분석·쉼터 공급자는 선택 기능의 착수 조건으로 분리한다.

- [ ] R1~R22 전부 검증됨

- [ ] 위치·알림 권한 거부와 위치 중단 상태가 각각 검증됨
- [ ] 분석 있음·부분·없음과 추천별 가용성이 각각 검증됨

# 구현 계획

## 10. 접근

### 이동 진행은 도메인 계산과 시스템 관측을 분리한다

`SweatDomain`은 선택 경로와 관측 위치를 받아 현재 위치를 경로 좌표열에 투영하고,
누적 진행 거리·남은 거리·예상 시간을 계산한다. 시스템 위치 타입과 실시간 표시 타입은
도메인으로 들어오지 않는다. GPS 흔들림으로 경로상 위치가 뒤로 보일 때는 같은 이동에서
확정한 최대 진행 거리를 유지한다.

`MoveData`는 위치 권한, `CLLocationUpdate.liveUpdates(.fitness)`,
`CLBackgroundActivitySession`, 로컬 알림을 감싼다. 이동을 시작할 때 세션을 열고 종료·취소·
실패 시 한 경로에서 정리한다. 화면 상태는 공급자의 비동기 이벤트를 값으로만 받는다.
SwiftUI 앱의 App Delegate 수명주기 훅은 백그라운드 위치 이벤트로 앱이 재실행될 때 저장된
미완료 이동을 즉시 복원하고, 화면이 나타나면 같은 추적 인스턴스를 이어받게 한다.

### 실시간 표시 타입은 앱과 확장이 공유한다

`MoveActivitySupport`에 `ActivityAttributes`와 갱신 정책을 두고 앱과 Live Activity 확장이
같이 의존한다. 앱은 하나의 활동을 시작·갱신·종료하고, 확장은 잠금 화면과 Dynamic Island를
DesignSystem 토큰으로 그린다. 지원되지 않거나 사용자가 비활성화한 경우에도 foreground
이동은 중단하지 않는다.

### 추천은 하나의 전체 상태가 아니라 각 근거별로 노출한다

앞 구간 분석, 공식 무더위쉼터, 대안 경로는 서로 다른 가용성으로 취급한다. 예를 들어 앞
구간 분석만 있으면 비단정 안내는 보이지만 쉼터와 우회 카드는 숨길 수 있다. 개발·미리보기의
고정 공급자는 Figma 상태 검증에만 사용하고 실제 응답처럼 번들 기본값으로 넣지 않는다.

### 검토했지만 택하지 않은 것

- 위치 간 직선거리만으로 진행률 계산 — 굽은 경로와 경로 이탈에서 오차가 커서 제외
- 매 위치 이벤트마다 실시간 표시 갱신 — 전력과 시스템 갱신 예산을 불필요하게 써서 제외
- 위치가 없을 때 시간만으로 진행률 증가 — 실제 이동하지 않아도 진행한 것처럼 보여 제외
- 일반 편의점을 무더위쉼터로 표시 — 공식 운영 여부를 보장할 수 없어 제외
- 분석 없음 상태에 `실외 100%` 적용 — 모름을 측정값처럼 보여 제외

## 11. 규칙 점검

| 규칙 | 해당 | 지키는 방법 |
|---|---|---|
| 단정하지 않는다 | ✅ | 체감과 현장 상태를 묻거나 `예상`, `~수 있어요`로 표현한다 |
| 추정치는 추정치로 | ✅ | 남은 시간·노출 감소 효과를 문구 가까이에서 예상값으로 표시한다 |
| 습도·풍속을 단계에 두 번 세지 않는다 | ✅ | 이동 추천은 확정된 단계와 경로 노출만 입력으로 받고 기상 요소를 다시 가중하지 않는다 |
| 경계값은 한 곳에 | ✅ | 진행 스냅·위치 stale·실시간 표시 throttle을 각 정책 타입 한 곳에 둔다 |
| 기록이 예측을 고친다 | ⬜ | 완료 값만 005 경계로 전달하며 보정은 005에서 구현한다 |
| 도메인은 순수하게 | ✅ | 진행·완료 모델은 Foundation만 사용하고 위치·실시간 표시 타입을 모른다 |
| 문구는 뷰 밖에 | ✅ | `MoveCopy`가 화면·실패·접근성 문구를 제공한다 |
| 색과 글꼴은 토큰으로 | ✅ | 앱과 확장 모두 DesignSystem 토큰을 사용한다 |
| 접근성은 마감이 아니다 | ✅ | 상태 결합 낭독과 접근성 크기 스크롤을 화면 작성과 함께 구현한다 |
| Swift 6 | ✅ | 위치 이벤트와 저장 상태를 `Sendable` 값으로 넘기고 actor 경계를 명시한다 |

## 15. 테스트 계획

| 대상 | 방식 | 케이스 |
|---|---|---|
| 진행 모델 | 단위 | 빈 좌표열, 시작·중간·도착, clamp 0~100%, GPS 후퇴, 경로 이탈 |
| 남은 값 | 단위 | 0 거리, 예상 시간 비례, 위치 중단 시 값 고정 |
| 위치 공급자 | 고정 대역·수동 | 권한 미결정·허용·거부, 일시 중단, 종료 뒤 이벤트 없음 |
| 실시간 표시 정책 | 가상 시계 단위 | 29초·30초, 4.9%p·5%p, 중복 시작, 종료 |
| 알림 | 고정 대역 | 허용·거부, 10분, 중복 방지, 이동 종료 시 취소 |
| 추천 가용성 | 단위 | 모두 있음, 각각만 있음, 부분 분석, 모두 없음 |
| 화면 상태 | 단위 | 시작, 추적, stale, 권한 거부, 종료, 복원 |
| 활성 이동 저장 | 단위 | 왕복, 12시간 만료, 완료·손상 상태 폐기 |
| 화면 | 스냅샷·수동 | Figma 두 상태, 긴 장소명, 402pt, `AX3`, VoiceOver |
| 통합 | 실기기 | background 위치, 잠금 화면, Dynamic Island 지원 기기, 앱 재실행 |
| 전력 | Instruments | 실기기 30분 이동에서 추가 사용량 8% 이하 목표 |

규칙 회귀 테스트는 분석값이 없을 때 `0%`, 편의점 `무더위쉼터`, 확정형 감소 효과 문구가
생기지 않는지 역검증한다.
